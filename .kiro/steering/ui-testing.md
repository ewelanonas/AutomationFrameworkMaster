# UI Testing

## What belongs in a UI test

Only what requires a browser:

- Critical user journeys end to end (login → core action → confirmation).
- Client-side behaviour: validation, dynamic rendering, state after refresh.
- Navigation, deep links, browser back/forward.
- Accessibility of key screens.
- Layout at supported breakpoints.

Everything else — business rules, permissions, field validation matrices,
error handling — belongs in API tests. A 40-case validation matrix driven
through a browser is a design error, not thorough coverage.

## Page object design

A page object is an interaction wrapper around a region of UI.

Rules:

- Locators are built once in the constructor and exposed as readonly
  properties. No selector strings outside the class.
- Methods are named for user intent: `submitPayment()`, `openCartMenu()`,
  `enterShippingAddress(address)`.
- No assertions inside. Return values or locators so the test asserts.
- No `Assert`/`expect`, no waits-for-assertions, no test framework imports.
- Navigation methods return the page object of the destination when the
  destination is deterministic.
- Split by region, not by URL. A screen with a complex table gets a
  `<Table>Component` used by the page.
- No inheritance chains deeper than one level (`BasePage` → `CheckoutPage`).
  Share behaviour by composition.
- A page object never creates test data and never reads config directly; both
  are injected.

## Locator strategy

Priority, best first:

1. `data-testid` — the only locator immune to copy and markup changes. When
   the app lacks one, add it in the app repo. That is a legitimate, expected
   part of automation work.
2. Role + accessible name — doubles as an accessibility assertion.
3. Label / placeholder / associated text.
4. CSS scoped to a stable container (`[data-testid=cart] .total`).
5. XPath — only for text-content or ancestor traversal that CSS cannot do.
   Never index-based, never absolute, never generated by a recorder.

Also:

- Never depend on generated class names, framework hashes, or `nth-child`
  positions in a list whose order is not part of the contract.
- Scope list item lookups by content: `getByRole('row').filter({ hasText: id })`.
- One locator per element. If two page objects need the same element, the
  element belongs to a shared component object.

## Waiting

- Rely on auto-waiting locators and web-first assertions as the default.
- When a genuine condition is needed, wait on the condition:
  a network response matching a predicate, an element state, or a polled
  API/DOM predicate with a timeout and a message naming what was expected.
- Timeouts come from the central policy: element (10s), navigation (30s),
  workflow (configurable, default 60s). Tests never hardcode milliseconds.
- Never sleep. Never `waitForLoadState('networkidle')` as a general-purpose
  wait — it is unreliable on apps with polling or analytics.

## Authentication

- Authenticate once per run through the API, save the browser storage state,
  and reuse it. Logging in through the UI in `beforeEach` is the single largest
  waste of time in most suites.
- Test the login screen itself in a small dedicated set of tests that do not
  reuse state.
- Each parallel worker gets its own account when the app mutates user-scoped
  state. Never share one account across concurrent workers.
- Store credentials only in environment variables. Never in a fixture file.

## Browser and viewport coverage

- Default gate: Chromium, desktop viewport, headless.
- Add Firefox and WebKit as a scheduled job, not on every PR, unless a
  browser-specific defect history justifies it.
- Responsive: cover the supported breakpoints as separate Playwright projects
  with device descriptors, not by resizing mid-test.
- Pin locale and timezone in config so date and number formatting is stable.
- Disable animations for stability where the app supports a reduced-motion
  media query; assert the reduced-motion behaviour itself once.

## Accessibility

- Run an automated a11y scan (`axe-core` via `@axe-core/playwright` or the
  language equivalent) on every key screen, in its own tagged test.
- Fail on new violations; maintain a reviewed baseline of known issues with
  ticket ids, never a blanket ignore.
- Prefer role-based locators everywhere — they exercise the accessibility tree
  as a side effect of normal testing.
- Cover keyboard-only navigation for critical flows: tab order, focus
  visibility, escape to close, enter to submit.
- Automated scans catch a minority of issues. Full WCAG conformance requires
  manual testing with assistive technology and expert review — say so rather
  than claiming a suite proves compliance.

## Visual testing

- Only alongside a functional assertion. A screenshot diff alone tells you
  something changed, not whether it is correct.
- Mask dynamic regions (dates, ids, avatars) with the masking option.
- Set a diff tolerance and store platform-specific baselines. Generate
  baselines in CI-equivalent containers, never on a developer laptop.
- Keep visual tests in their own tagged suite so a rebrand does not block
  functional coverage.

## Failure diagnostics

Every UI test failure must automatically attach: screenshot at failure, full
page HTML, Playwright trace, video, console errors, failed network requests,
the resolved locator of the failing step, and the correlation id. Retain on
failure only.

Console errors deserve their own assertion: collect `pageerror` and
`console.error` during the test and fail if the page logged an unexpected
error, with an allowlist for known third-party noise.

## Anti-patterns

- Login through the UI before every test.
- One test that walks ten screens with thirty assertions.
- Selector strings, `sleep`, or assertions inside page objects.
- `if (await el.isVisible())` to handle "sometimes there is a banner" — make
  the state deterministic instead.
- `force: true` on clicks to get past an overlay.
- Asserting on `innerText` of a whole page.
- Tests that depend on data another test created.
- Serial mode used to hide shared state.
- Recorded, generated page objects committed without cleanup.
